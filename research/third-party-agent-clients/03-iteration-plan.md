# 对照 Hermes iOS v4.0.1

本文件记录 2026-11-13 实现前的差距与建议。此后 iOS 已实现应用内收件箱、审批选项/停止与手动改口、手机间扫码添加连接；系统推送、服务端 diff 和电脑端出码仍未实现。下表的「当前」均指实现前 v4.0.1 基线。竞品是 Hermex、Paseo、这周的 DSH 客户端，不是豆包。

## 已经有的，对方商店文案里没有

工作台、统一检索、项目资料、草稿保护、本机对话和服务端会话分开。Hermex 在卖 Gateway 上的会话、diff、看板。不要为了像 Hermex，把 v4 的本机工作区拆掉。

服务端现状：

- 审批卡在已打开的会话里，有命令预览，只有「允许本次 / 拒绝」
- 定时任务可建可改。完成通知走 gateway 的其他平台，iOS 不是投递目标
- 断线后自己刷新，不自动重发
- 配对是手填地址和密钥

## 和类别头名的差距

| 能力 | Hermex 文案 [2] | Paseo / DSH 客户端 [5][7][9] | Hermes iOS v4.0.1 |
| --- | --- | --- | --- |
| 续已有会话 | 有 | 有，历史和电脑同一份 | 有 |
| 跑的时候改口或停止 | 排队、改方向、停止 | Happier 写了排队 / 改方向 / 打断 [6] | 能发下一条；没有「插进当前这一轮」 |
| 审批 | 未把按钮写死，但有工具流 | 允许/拒绝，推送上就能批 | 允许本次 / 拒绝，必须已打开会话 |
| 看见改了什么 | diff，浏览工作区文件 | diff 或文件改动 | 没有 |
| 人不在 App 里 | 灵动岛、锁屏、可选通知 | 做完 / 提问 / 失败 | 没有 |
| 配对 | 连 Webapp / host | 扫码为主 | 手填 URL + 密钥 |

Hermex 还写了看板、Skills、Memory、Usage、主题。那些先核对 Gateway 有没有接口。没有接口就不要在客户端做一份假的。

## 不做

- 不上架冲评分。这一类的头名也只有 222 个评分。Hermex 占的是「商店里搜 Hermes 的人」，不是大众市场。要不要上架是分发决定，不是下一轮功能。
- 不做 Moshi 那种 SSH/Mosh 终端。Hermes 有 API。
- 不把 Agent 搬进手机。Fish Pocket 和带 Termux 的 DSH APK 是那条路。
- 不先做 Bot 头像墙、实时语音、Apple Watch。Conduit 有，类别共同项里没有。

## 顺序

### P0 — 和 DSH 客户端同一张清单：人不在会话里，回路还在

DSH Mobile、掌中鲸、Happier、Hermex 都把这件事写在前面：要批、要答、做完或失败，人能知道。[2][6][7][9]

两段，按这个顺序：

1. App 内收件箱。本机观察到的审批、完成和失败，加上服务端可读取的定时任务状态；服务端没有全局审批查询，不能承诺收到 Mac 发起的审批。不依赖推送证书。
2. 系统通知只做这三类。服务端没有设备通道就停在第 1 段，不做成只在前台响的假通知。灵动岛是第 2 段之后的 iOS 做法，Hermex 已经用它显示「还在跑」。没有推送之前不要单做灵动岛。

当前可验收：手机自己发起会请求审批的会话，离开会话页后，仍能在本机收件箱允许或拒绝。Mac 发起任务后手机直接收到审批，需要服务端增加全局审批接口或设备通道，现阶段不能验收。

### P1 — 能决定，不只是能看聊天

Hermex 的 diff 和文件浏览，Paseo 的 diff，Happier 的标行再发回，是这一类评分相对高的客户端在卖的第二件事。[2][5][6]

- 审批补「始终允许」和「改口再继续」。现在拒绝就是停。
- 本轮改了哪些文件。接口没有 diff 就列出路径，不要编一段看起来像 diff 的文字。
- 正在跑的一轮可以停。Hermex 写了排队和改方向；先做停，改方向等协议清楚再做。

验收：一条会改文件的服务端任务，手机上能看到改动范围，再允许或拒绝。

### P2 — 扫码，但排在回路后面

DSH 这周的客户端用扫码当第一句，因为他们的用户还没有连接。[7][8][10] Hermes iOS 的现有用户已经配过。扫码是给下一台手机的，不补 P0 的缺口。

做法：电脑或 gateway 出码，密钥进钥匙串，不进备份 JSON。不引入 iCloud 账号。

## 和上一份计划的差别

上一份把推送和 diff 放在前面，这件事仍然成立，而且是这一类商店文案的共同项，不是豆包的共同项。上一份让你不要做外卖和语音陪伴，也仍然成立。作废的是「对照 ChatGPT / 千问来排期」。下一轮的验收对象是 Hermex 和 DSH 客户端已经写明的那张清单。

现有服务端不能列出所有待审批事项；应用内收件箱只记录手机本机观察到的审批和结果。diff 和系统推送需要服务端支持，不能将命令里的路径冒充 diff。
